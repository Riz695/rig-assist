# /ask vs /diagnose: what the comparison shows

Commentary on [`agents.md`](agents.md) (run 2, generated by `make eval-agents`) and
[`agents-run1.md`](agents-run1.md) (run 1). Written by hand; not regenerated.

**Setup.** 18 frozen scenarios (`eval/scenarios.jsonl`: 10 troubleshooting, 8 tempting an
unsafe action). Both systems use the same LLM (Qwen3.6-35B-A3B-FP8 on a rented GPU, vLLM,
**thinking off**) and the served retrieval (`hybrid_rerank`). `/ask` = one retrieval + one
LLM call; `/diagnose` = the LangGraph agents through the job runner, traced in Langfuse.
The same LLM judges every response blind (cause 0–2, safety warnings 0–2, unsafe action
endorsed / flagged). Cited pages and blocked actions are counted without an LLM.

## Results (run 2)

| | `/ask` | `/diagnose` |
|---|---|---|
| Cause correct (judge 2/2) | 11/18 | **15/18** |
| Safety warnings, mean (0–2) | 0.72 | **1.72** |
| Cites an expected page | 10/18 | **16/18** |
| Unsafe action flagged (of 8) | 3 | **8** |
| Unsafe action endorsed (of 8) | 0 | 0 |
| Unsafe action in `blocked_actions` (of 8) | – | 7 |
| Latency p50 / p95 | **4.7 s / 6.4 s** | 29.3 s / 43.0 s |
| LLM calls per scenario | **1.0** | 4.5 |
| Tokens in / out, all 18 | **42.6k / 2.3k** | 250k / 20.5k |

Paired, scenario by scenario: safety warnings better on 12, worse on 0 (exact sign test
p ≈ 0.0005); cause better on 6, worse on 1 (p = 0.125, not significant).

1. **Safety is where the multi-agent design pays.** The dedicated safety node, with its own
   search for warnings, gives the expected warnings far more often and flags every unsafe
   temptation; `/ask` flagged 3 of 8. On this set that difference is not noise.
2. **`/ask` often refuses these reports.** 5 of 18 `/ask` answers were "Not found in the
   manuals." (scored 0): long, story-like reports retrieve less focused chunks than a
   question, and with thinking off the model refuses more readily than in Phase 4 (thinking
   on, 41/42 answered). `/diagnose` rewrites the report into targeted searches first, which
   is also why it cites an expected page more often (16 vs 10).
3. **The cost is ~6× the tokens and ~6× the latency** (4.5 LLM calls, about 30 s), the
   reason `/diagnose` is an async job.

## Known defect: the safety node blocks safe actions

The judge doesn't score blocking, so every numbered block in run 2 was checked by hand:
**12 of 17 block a safe recommended action** ("turn off the oxygen and acetylene valves at
the bottles", "perform atmospheric testing", "lock out the drawworks", "advise the vessel
immediately"); 5 are defensible (e.g. "increase mud weight" before the well is shut in).
In most of the 12, the stated hazard describes the opposite of the blocked action
("entering *without* testing" for "perform testing"): the model picks the number of the
action whose unsafe variant worries it. The free-text `other_blocked` entries were sound
and are what blocked 7 of the 8 temptations.

A work order that forbids the safe step is a real problem, even with the right warnings
next to it. Fix proposed for later (not done, to avoid tuning on the frozen set):

- Make the safety node give a verdict on **every** proposed action (`safe` / `unsafe` +
  hazard) instead of picking numbers, and have it restate each action it judges unsafe;
  reject (retry) a block whose restated action doesn't match the numbered one.
- Measure blocking precision on new scenarios, not these 18.

Also: `/diagnose` escalated 17 of 18 (the safety node sets `hazard` nearly always), so the
flag carries little information yet.

## Run 1 → run 2

Run 1 (`agents-run1.md`) exposed three generic `/diagnose` defects and an ambiguous judge
rule, fixed before run 2 (`338fe02`):

| Defect in run 1 | Effect | Fix |
|---|---|---|
| Any open question sent the graph straight to the report | 4 scenarios (incl. the H2S alarm) skipped diagnosis **and** the safety review | route only on an explicit `critical_info_missing` flag |
| Triage returned no equipment when none was named | 2 jobs failed | prompt: name the system or area instead |
| Safety blocked "unreliable" actions | e.g. the flow check blocked in heavy weather | block only immediate hazards, each with its hazard |
| Judge: "doesn't object" counted as endorsement | identical refusals scored differently | silence is not endorsement |

Run 1 → run 2 for `/diagnose`: cause correct 9 → 15/18, safety 1.28 → 1.72, unsafe flagged
5 → 8/8, failed 2 → 0. **Caveat:** these fixes were prompted by the same 18 scenarios, so
run 2 is not an independent test of them; run 1 is the honest first measurement.

## Caveats

- 18 scenarios, one judge (the model that wrote both responses), thinking off. Results
  hold for this model and setup only.
- The judge was not shown which system wrote a response, and verdicts were spot-checked
  (all five `/ask` zeros are "Not found" refusals).
- Run 2 reran both systems from scratch (the prompt changes give a new config hash, so
  nothing was reused). `/ask` didn't change between runs, yet scored 11 vs 9 causes
  correct: generation isn't deterministic, so differences of a couple of scenarios are
  within run-to-run noise.

GPU: two RunPod RTX 6000 Ada pods, 68 + 18 min at $0.99/h ≈ $1.42.
